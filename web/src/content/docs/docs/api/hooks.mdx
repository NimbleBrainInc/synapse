---
title: React hooks
description: AppProvider and the hooks over it — tool calls, data sync, theming, host context, agent context, actions, files, and long-running tasks.
---

Everything React lives at `@nimblebrain/synapse/react`. Wrap your tree in
`<AppProvider>`, then use the hooks below. There is one provider and one hook
family; a hook used outside the provider throws rather than returning something
half-connected.

```tsx
import { AppProvider } from "@nimblebrain/synapse/react";

createRoot(document.getElementById("root")!).render(
  <AppProvider name="my-app" version="1.0.0">
    <App />
  </AppProvider>,
);
```

`<AppProvider>` takes the same options as [`connect()`](/docs/api/connect/) and
**renders nothing until the handshake completes**, so nothing below it can
observe an app that is not connected yet.

Each hook checks what the host declared before it sends anything. The **Without
it** column says what the hook does when the host did not declare the capability
it needs. The [portable-app contract](/docs/concepts/degradation/) has the
reasoning.

## Host state

| Hook | Returns | Description | Without it |
| --- | --- | --- | --- |
| `useApp()` | `App` | The connected app | n/a |
| `useTheme()` | `Theme` | The current theme. Re-renders only when the theme actually moves — a host-context change that leaves it untouched does not re-render your components. | Needs nothing. Neutral defaults when the host sends no tokens. |
| `useHostContext<T>()` | `T` | The full host context, including host extensions. Re-renders on every change. | Needs nothing. Host-only fields are `undefined`. |
| `useToolResult()` | `ToolResultData \| null` | Re-renders on every `tool-result` event | Needs nothing. `null` until the host sends one. |
| `useToolInput()` | `Record<string, unknown> \| null` | Re-renders on every `tool-input` event | Needs nothing. `null` until the host sends one. |
| `useResize()` | `(w?, h?) => void` | Resize helper, auto-measures body if no args | Needs nothing. Always sent. |

## Tools

| Hook | Returns | Description | Without it |
| --- | --- | --- | --- |
| `useCallTool(name)` | `{ call, data, isPending, error }` | Call a tool on this app's own MCP server with loading/error state. `call(args?)` fires it. | `serverTools`: `call` rejects with `HostCapabilityError`, and `error` holds it. |
| `useCallToolAsTask(name)` | `{ fire, task, result, error, isWorking, isTerminal, cancel }` | The full MCP task lifecycle for a long-running tool. See [long-running tools](/docs/guides/long-running-tools/). | The tasks capability: `fire` rejects with `HostCapabilityError`. Check `app.supportsTasks`. |
| `useDataSync(cb)` | none | Run `cb` when your server announces its data changed (`notifications/resources/list_changed`). `cb` receives the notification's params. See [keep the UI in sync](/docs/guides/keep-ui-in-sync/). | `serverResources.listChanged`: `cb` never runs. |

## Agent-facing state

| Hook | Returns | Description | Without it |
| --- | --- | --- | --- |
| `useModelContext()` | `(state, summary?) => void` | Push what the user is looking at to the agent, debounced 250 ms | `updateModelContext`: no-op |
| `useModelContext(factory, deps)` | none | The same, pushed whenever `deps` change | `updateModelContext`: no-op |
| `useSendMessage()` | `(text, context?) => void` | Send a message into the agent conversation | `message`: no-op |

The debounce lives in the hook rather than on `app.updateModelContext`, which
sends immediately: a selection the user drags through should cost one frame, not
thirty, and that problem is a React one.

## NimbleBrain extensions

Not part of the MCP Apps spec. Each works only on a host that declares it in
`hostCapabilities.experimental`. `hostSupports(app, extension)` tells you whether
it did.

| Hook | Returns | Description | Without it |
| --- | --- | --- | --- |
| `useAction()` | `(name, params?) => void` | Trigger a host-side action | `ai.nimblebrain/action`: no-op |
| `useFileUpload()` | `{ pickFile, pickFiles, isPending }` | The host's native file picker | `ai.nimblebrain/request-file`: both reject with `HostCapabilityError` |
